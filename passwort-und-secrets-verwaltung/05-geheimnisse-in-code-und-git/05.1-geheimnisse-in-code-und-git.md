## Lernziele

Nach dieser Übung kannst du

- Geheimnisse in Dateien mit einem Scanner suchen und dessen Grenzen nennen

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

1. Siehe `beispiele/leckscan.ausgabe.txt`: Der Scanner findet nur `app.py` (Treffer 1). `DB_PASSWORD=…` in `config.env` wird nicht erkannt, weil das Muster `password` als eigenes Wort verlangt und der Unterstrich zum Wort gehört; `grep -rin password` findet beide Dateien.
2. Nach dem Löschen steht die Datei nicht mehr im aktuellen Stand, aber `git log -p` zeigt den Wert noch („2 Treffer“, später insgesamt 4). Folge: Rotation.
3. Wert aus dem Code (Umgebungsvariable), Datei in `.gitignore`, Vorlage `config.env.beispiel` einchecken.
4. Der Hook bricht den Commit mit Rückgabecode 1 ab („mögliches Geheimnis in neu.py“); er läuft nur lokal.

**Kontrollfragen (Antwortskizzen):**

1. Der Verlauf enthält alte Fassungen; `git log -p` zeigt den Wert weiter.
2. Das Geheimnis als bekannt behandeln und ersetzen (Rotation).
3. Eine Vorlage ohne Wert zeigt, welche Einträge nötig sind.
4. Er läuft lokal und lässt sich umgehen; er ersetzt keine Prüfung auf dem Server.

</details>
