# 09.1 Host-Firewall für den Server

|---|---|
| **Modul** | 09 Host-Firewall (Priorität 1) |
| **Stufe** | Grundlagen |

> [!WARNING]
> **Stand der Prüfung: Skript im Container ausgeführt.** **Nicht in einer VM ausgeführt.** Die Skripte liefen in einem Cloud-Container (Ubuntu 24.04, ohne systemd, ohne AppArmor und SELinux im Kernel); Verhalten auf Debian 12 und mit systemd ist nicht geprüft. 

## Lernziele

Nach dieser Übung kannst du

- ein Server-Regelwerk mit Default-Drop in nftables lesen und schreiben
- SSH nur aus dem Verwaltungsnetz und mit Rate-Limit erlauben
- eine Firewall-Änderung so einführen, dass man sich nicht aussperrt
- die Grenzen eines Frontends wie `ufw` benennen

## Voraussetzungen

- Modul 5
- Grundlagen nftables aus dem Kurs „Linux-Firewall mit nftables und iptables“ (nur Überblick nötig)

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Default-Drop | Standardentscheidung der Eingangskette: verwerfen |
| `ct state` | Zustand der Verbindungsverfolgung (new, established, related, invalid) |
| Set | benannte Menge von Adressen oder Ports in nftables |
| `ufw` | einfaches Frontend für Netfilter-Regeln |
| Aussperrschutz | Maßnahme, die eine fehlerhafte Regel automatisch zurücknimmt |

## Laborumgebung

| Was | Rolle in Modul 09 |
|---|---|
| `vm01` | Linux-Server-VM, Rechte: root bzw. sudo |

## Mitgelieferte Dateien

| Datei | Zweck |
|---|---|
| `firewall_test.sh` | Lädt server_firewall.nft im Namespace "srv" und prüft aus dem Namespace "cl": erlaubte und gesperrte Zugriffe, Zähler, Quelladresse. |
| `server_firewall.nft` | Host-Firewall für den Server: alles verbieten, was nicht erlaubt ist (inet = IPv4 und IPv6). |

## Aufgabe

### Aufgabe 1 – Dienste und Quellen festlegen (Einheit 9.1)

Legen Sie für `vm01` fest, welche Dienste (Port, Protokoll) aus welchen Quellnetzen erreichbar sein sollen, und schreiben Sie das als Tabelle. Begründen Sie, welche Verbindungen ausgehend erlaubt bleiben.

### Aufgabe 2 – Regelwerk anpassen (Einheit 9.2)

Passen Sie `server_firewall.nft` an die Tabelle aus Aufgabe 1 an (Adressen, Ports). Prüfen Sie die Syntax mit `nft -c -f`, laden Sie es und prüfen Sie mit `nft list ruleset`.

### Aufgabe 3 – ufw im Trockenlauf (Einheit 9.3)

Geben Sie auf `vm01` die ufw-Befehle für dieselben Freigaben ein, zunächst mit `ufw --dry-run`, und vergleichen Sie die erzeugten Regeln mit Ihrer nftables-Datei. Nennen Sie zwei Dinge, die Sie mit ufw nicht so genau ausdrücken können.

### Aufgabe 4 – Test und Aussperrschutz (Einheit 9.4)

Führen Sie `bash firewall_test.sh` aus und erklären Sie jede Zeile. Beschreiben Sie, wie Sie das Regelwerk auf `vm01` laden, ohne sich auszusperren (zweite Sitzung, zeitgesteuerter Rückfall mit `at`, `nft -c`).

## Hinweise

- Der Test läuft in Namespaces mit nftables 1.0.9; `ufw --dry-run` wurde **nicht** ausgeführt (Aufgabe 3 ist Fachwissen).
- Die Verbindung für die Rate-Limit-Zählung hängt von vorherigen Tests ab (Zähler wirken seit dem Laden).
- Auf `vm01` ist `nft` unter Debian 12 vorhanden; ob der Dienst `nftables.service` die Datei beim Start lädt, ist in der VM zu prüfen (nicht bestätigt).
- IPv6 wird durch die `inet`-Tabelle mitbehandelt, aber im Test nicht geprüft.

## Kontrollfragen

1. Warum werden `ct state established,related` und die Loopback-Schnittstelle vor dem Drop-Eintrag erlaubt?
2. Warum gehört `ct state invalid drop` vor die Dienstregeln?
3. Was bewirkt `limit rate 6/minute burst 6 packets` bei SSH, und welche Nebenwirkung hat es?
4. Was ist der Vorteil eines Sets für Verwaltungsadressen gegenüber mehreren Einzelregeln?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

1. Beispiel: TCP 22 nur von `10.14.0.2`, TCP 8080 für alle, ICMP-Echo begrenzt; alles andere verworfen.
2. Die Datei `server_firewall.nft` ist ein Beispiel; `nft -c -f` prüft ohne zu laden.
3. Beispiel: `ufw default deny incoming`, `ufw allow from 10.14.0.2 to any port 22 proto tcp`, `ufw allow 8080/tcp`, `ufw limit 22/tcp`; nicht ausgeführt. Grenzen: Sets und Zustandsprüfung feiner Art lassen sich nur eingeschränkt ausdrücken.
4. Siehe `beispiele/firewall_test.ausgabe.txt`: Vorher alles erreichbar; nachher 22 nur von `10.14.0.2`, 8080 für beide Quellen, 3306 gesperrt; Zähler der Drop-Regel.

**Kontrollfragen (Antwortskizzen):**

1. Antwortpakete bereits aufgebauter Verbindungen und lokale Kommunikation würden sonst verworfen und der Server wäre faktisch nicht nutzbar.
2. Ungültige Pakete sollen gar nicht erst in Dienstregeln gelangen und werden früh verworfen.
3. Es begrenzt neue Verbindungen auf sechs pro Minute (mit Spitze von sechs); ein Angreifer wird gebremst, aber auch ein Administrator mit vielen schnellen Verbindungen (im Test erfolgreich: 5 von 8).
4. Ein Set hält Adressen an einer Stelle, lässt sich zur Laufzeit ändern und macht Regeln kürzer und lesbarer.

</details>
