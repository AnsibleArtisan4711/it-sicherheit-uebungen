## Aufgabe

### Aufgabe 1 – Risiko erklären (Einheit 7.1)

Erklären Sie in fünf Sätzen, warum ein gleiches lokales Administratorkennwort auf vielen Rechnern ein Risiko ist (seitliche Bewegung) und wie LAPS es mindert.

### Aufgabe 2 – Einrichtung beschreiben (Einheit 7.2)

Beschreiben Sie die Schritte zur Einrichtung in Ihrer Testdomäne: Schema erweitern, Rechner dürfen ihr Kennwort schreiben, wer darf lesen, Richtlinie, Verschlüsselung. Nennen Sie die Cmdlets aus der Dokumentation und kennzeichnen Sie, dass Sie sie nicht ausgeführt haben.

### Aufgabe 3 – Ablauf prüfen (Einheit 7.3)

Führen Sie `python3 laps_pruefen.py computer_export.csv` aus. Erklären Sie die Auffälligkeiten; rechnen Sie ein FILETIME-Beispiel von Hand in ein Datum um (Hinweis: 100-Nanosekunden-Schritte seit 1601).

### Aufgabe 4 – Abruf regeln (Einheit 7.4)

Legen Sie fest, wer Kennwörter lesen darf, wie der Abruf protokolliert wird und wann nach Gebrauch rotiert wird. Beschreiben Sie, was nach einem Zurücksetzen einer VM auf einen Prüfpunkt passiert.

## Hinweise

- Windows LAPS gilt laut Dokumentation ab Windows Server 2019; das alte Microsoft LAPS ist ab Windows 11 23H2 veraltet. Die Cmdlet-Namen (`Update-LapsADSchema`, `Set-LapsADComputerSelfPermission`, `Set-LapsADReadPasswordPermission`, `Get-LapsADPassword`, `Invoke-LapsPolicyProcessing`, `Reset-LapsPassword`) stammen aus der Dokumentation, ihre Wirkung wurde **nicht ausgeführt**.
- Der Attributname `msLAPS-PasswordExpirationTime` ist Fachwissen (nicht bestätigt); `msLAPS-CurrentPasswordVersion` steht in der Dokumentation.
- Das Skript gibt das erzeugte Kennwort nie aus.

## Kontrollfragen

1. Wo speichert Windows LAPS das Kennwort bei Active Directory?
2. Was verlangt die Verschlüsselung der Kennwörter in AD?
3. Warum kann das Zurücksetzen einer VM auf einen Prüfpunkt LAPS stören?
4. Warum soll einem Rechner nie erlaubt sein, Kennwörter zu entschlüsseln?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

1. Gleiches Kennwort überall: ein gestohlener Hash öffnet viele Rechner; LAPS vergibt je Rechner ein eigenes, wechselndes Kennwort.
2. Schema erweitern, Selbstschreiben-Recht pro OU, Lese-Recht für eine Gruppe, GPO mit Kontoname, Länge, Alter, Verschlüsselung; Cmdlets s. o. (nicht ausgeführt).
3. Siehe `beispiele/lauf.ausgabe.txt`: ein Rechner mit abgelaufenem Kennwort, einer ohne Kennwort.
4. Lesegruppe klein, Überwachung der Zugriffe, Rotation nach Abruf (`Reset-LapsPassword`); Prüfpunkt-Rücksetzung führt zu einem unpassenden Kennwort (siehe Antwort 3).

**Kontrollfragen (Antwortskizzen):**

1. Am Computerobjekt, gesichert durch Zugriffsrechte und optional Verschlüsselung.
2. Mindestens die Domänenfunktionsebene Windows Server 2016 (laut Dokumentation).
3. Das gespeicherte Kennwort passt dann nicht mehr zum lokalen; ab Windows Server 2025 / Windows 11 24H2 erkennt Windows LAPS das und rotiert sofort.
4. Die Dokumentation empfiehlt, keinem Gerät das Entschlüsseln zu erlauben, auch nicht für sich selbst.

</details>
